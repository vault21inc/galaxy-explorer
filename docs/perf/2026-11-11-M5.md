# Performance report: M5, 2026-11-11

Written by `pnpm perf` (scripts/perf/) against the budgets in [rendering.md §2](../plan/rendering.md#2-performance-budget). **Every budget is met.**

## Setup

- **Machine:** Mac16,5, Apple M4 Max, 128 GB, macOS 26.6.2.
- **Code:** commit `c87259b` plus uncommitted changes; a production build with the test hooks (`VITE_TEST_HOOKS=1`).
- **Browsers:** chrome 157.0.8103.39; webkit 27.2. Headed, 1440 × 900 CSS px at device pixel ratio 2, default quality (Medium: DPR capped at 1.5).
- **Timers:** WebKit rounds `performance.now()` to whole milliseconds, so its frame times carry ±1 ms; the 60 fps check allows it that, and its label timings aren't judged.
- **Display refresh rate, measured:** chrome 238 Hz, webkit 59 Hz. Frame intervals can't be shorter than the display's.
- **Mode:** view mode, as a reader sees it.
- **Content:** the stress map, 5,000 objects (300 groups and 50 routes are drawn from M4).
- **Path:** load; 3 s idle; orbit (3 left-drags); pan (2 right-drags); zoom toward the cursor (100 wheel steps at two points); orbit again holding Space (every label shown). Then the system view: the map's first system made busy (1 star, 12 planets, one ringed, 2 belts, 5 stations); 3 timed entries and exits; orbit (3 left-drags) and zoom (48 wheel steps over empty space) inside it; 20 more round trips. 3 s idle after each phase. Pointer steps are 16 ms apart.

## Notes

- **The transitions were shortened to meet the budget.** At the plan's first step lengths (fly 350 ms, fade out 150 ms, fade in 300 ms), entering and leaving took about 835 ms with data cached, over the 700 ms budget. The steps are now 260, 120 and 220 ms (`VIEW_FLY_MS`, `VIEW_FADE_OUT_MS`, `VIEW_FADE_IN_MS`). Times run from the request to the faded-in new view, as `__GE_TEST__.enter()` and `exit()` resolve, polling every 20 ms.
- **The first entry is shown but not judged.** At about 1 s, it also downloads the system view's code and its payload. Zooming in prefetches the payload once the system is the zoom target (M5-T2), so a reader's first entry usually waits only for the code.
- **GPU memory** is level across the 20 round trips: 15 geometries and 7 textures before and after, in both browsers. The seventh texture is the star granulation, baked on the first entry and kept by the bake cache. The e2e leak test (`e2e/leaks.spec.ts`) checks the same on the demo map in CI.
- **Triangles differ between browsers.** WebKit reports about twice Chrome's triangles in the system view (140,728 against 71,468) for the same 9 draw calls. The galaxy view's counts match. It may be how WebKit's driver counts instanced draws; draw calls and frame times are the budgets, and both are within them.
- The edit-mode run (`pnpm perf --edit`) still covers the galaxy view only.
